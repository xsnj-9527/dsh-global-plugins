# 开工前的需求分析

用户级策略 `~/.dsh/AGENTS.md` 第 1 节要求：**每个任务先分析需求，再动手**。本技能是那一步的完整做法。

目的是**少返工**，不是走流程。分析要短，判断要准，问要问在刀刃上。

## 一、六项检查清单

逐条过一遍，只花十几秒：

| # | 检查项 | 典型症状 | 处理 |
|---|---|---|---|
| 1 | **交付物是什么** | 说了要做什么，没说做完长什么样 | 能推断就推断；推断不了就问 |
| 2 | **指代与范围** | "那个东西""这个项目""顺便清理一下" | 指代对象、范围边界必须唯一确定 |
| 3 | **程度与取舍** | "优化一下""弄好看点""尽量快" | 明确优化目标与优先级（快/稳/省/可读） |
| 4 | **逻辑自洽** | 要求互相矛盾、缺前置条件、顺序不可能 | 指出矛盾本身，让用户裁决，不要自己挑一个 |
| 5 | **关键参数** | 路径、目标对象、格式、时间范围 | **先自己查**；查不到才问 |
| 6 | **风险与不可逆** | 删除、覆盖、对外发布、发消息、花钱、改线上 | **一律显式确认**，不代替用户决定 |

## 二、先自查，再提问

提问前必须排除"我自己就能查清"的问题。以下都**不许问**：

- 项目结构、文件在哪、函数怎么实现、用了什么库、版本号；
- 某个配置项当前值、某段代码现在怎么写的；
- 历史操作记录（会话记录、日志、git 历史能查到的）；
- 工具是否可用、环境里装没装某个东西。

这些靠 `read` / `grep` / `glob` / `bash` 自己解决。**拿这类问题占用用户时间是不合格的。**

## 三、确有问题时：一次问清

- 用 `ask_user_question`，**最多 3 条**，每条 2~5 个候选选项，并把自己推荐的那个放在第一位、标注"（推荐）"。
- 每条问题必须**直接决定接下来怎么写代码/怎么做**，不要问"你希望我怎么做呢"这种空问题。
- 问完把用户的选择**复述一句**，然后立刻开工。不要问完又反问，也不要多轮盘问。
- 用户已经说过的内容不要再问一遍。

### 提问模板

```json
[
  { "id": "scope",   "header": "改动范围",
    "question": "《双生花》里要改的\"数值\"，是指阿比盖尔的攻击力/亮度那一组可调设置，还是温蒂自身的血量与理智恢复速度？",
    "options": [
      { "label": "阿比盖尔那一组设置（推荐）", "description": "对应 modinfo.lua 里的 6 个可调项，只动默认值。" },
      { "label": "温蒂自身的数值",             "description": "涉及 modmain.lua 里的恢复逻辑，改动面更大。" },
      { "label": "两者都改",                   "description": "我会分两批提交，便于你逐个验收。" }
    ] },
  { "id": "risk", "header": "是否直接发布",
    "question": "改完之后要不要立刻上传到创意工坊？",
    "options": [
      { "label": "先不上传，我验收后再说（推荐）", "description": "只改本地文件，不触碰线上条目。" },
      { "label": "直接上传",                       "description": "会更新已发布的工坊条目 3800006179。" }
    ] }
]
```

### 反例（不要这样问）

| 反例 | 为什么不行 |
|---|---|
| "请问您具体想要什么呢？" | 空问题，用户已经说过了 |
| "代码在哪个目录？" | 自己能查，`glob` 一下就有 |
| "要不要我顺便把注释也加上？" | 与当前目标无关的搭车提问，制造决策负担 |
| 连续三轮追问细节 | 应该在第一轮把 3 个关键问题一次问完 |
| 明知有风险却不问，先做了再说 | 删除/覆盖/发布类操作不可逆，必须先确认 |

## 四、没有问题时的开场

用 **2~4 行**写清三件事，然后直接开工：

```
目标：把《伍迪真无敌》的鹿人攻击力默认值从 500 调到 300。
假设：只改默认值，不新增设置项；改完先不上传，等你验收。
计划：改 modmain.lua → 本地语法检查 → 报告待上传状态。
```

不要写成十行方案书，也不要等用户点头才动手——**没有真问题就直接做**。

## 五、可以整段跳过的场合

- 纯只读查询：看文件、列目录、跑状态查询、查资料；
- 单步琐碎操作：改一个错别字、跑一条命令、回答一个知识问题；
- 用户已经给出了完整规格（目标、范围、参数、验收标准都齐）。

这些直接做。**分析是为复杂或有歧义的任务准备的。**

## 六、与其它规则的优先级

更具体的规则优先：plan 模式的要求、动态 Cordis 插件的既定流程、
以及 `~/.dsh/AGENTS.md` 第 2 节"DST 上传只允许一条命令"，都覆盖本节的一般性描述。

上传类任务注意：分析阶段**可以**用 `--status` / `--list` 查状态（只读、秒回），
但**不要**为了"确认理解"去试传一次。
